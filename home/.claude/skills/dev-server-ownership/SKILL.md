# Dev server ownership

Directive: stop only the dev server this session started. Before any kill, prove ownership: the listener's working directory must be your own worktree or checkout.

When you start a server, record its pid at launch: `nohup <cmd> > <scratch>/<name>.log 2>&1 & echo $! > <scratch>/<name>.pid`. Keep the log in your scratch directory, not a shared path. Later stops use the recorded pid tree (step 3), so `lsof` guessing is only needed for servers you did not start.

1. Find the listener: `lsof -tiTCP:<port> -sTCP:LISTEN`.
2. Confirm ownership per pid: `lsof -p <pid> | grep cwd`. A different cwd means another session's server: leave it and pick a free port. Check this before you judge a branch by what a running server shows. A listener whose cwd is another worktree serves that worktree's code, so a correct branch can look broken. Start your own copy from your worktree on a free port and test there.
   Never print full process args or env for these pids (`ps -o command`, `ps eww`): dev servers carry secrets in env (e.g. `GITHUB_REGISTRY_TOKEN`), which lands in the transcript. Use `ps -o pid=,ppid=,comm= -p <pid>` or `pgrep -P <pid>` to map the tree. If a secret shows anyway, flag it to the user for rotation.
3. Kill the whole tree: the `npm exec` or `pnpm` parent, the framework server (`next-server`), and its worker children. Killing only the listener leaves workers holding the port. Kill by the pids from `lsof` and `pgrep -P` after the cwd check. Never `pkill -f <path pattern>`: it matches any process whose args contain that text, not only this session's. Piping `ps -o command=` through `cut` still prints args, so do not use it either.
4. Verify: `lsof -iTCP:<port> -sTCP:LISTEN` prints nothing. Never trust `lsof ... | head; echo "exit $?"`: that status is `head`'s, so "exit 0" says nothing about the port. Read lsof's own output (empty means free). A `next-server` pid can survive the first TERM while its postcss workers exit; if the listener is still there, TERM that pid again after a few seconds and re-check. Leave shared backends on other ports running. Restarting a shared backend (for example Medusa on :9000, to pick up env or CORS changes) drops every teammate's storefront and admin for about a minute: announce it to the user before and after.

Storefront port clash: `pnpm dev` hard-codes `-p 8000`. When another session holds that port, run `pnpm exec next dev --turbopack -p <free port>` directly, and leave the holder running. A request to start a server for `main` goes in a detached worktree of `origin/main` (`git worktree add --detach <path> origin/main`), with the `.env` files copied from a worktree that has them, never in the main checkout. Stopping another worktree's servers to free ports is allowed only when the user asked for that switch; prove each cwd first, and report which ports moved. A worktree's `.env` copied from main keeps the public base-URL var (e.g. `NEXT_PUBLIC_BASE_URL`) at the default port `:8000`. Run on another port and login redirects to `:8000`, so the form silently stays on the login page and Playwright fails on `login-page`. Set that var to your port in your own worktree's `.env` and restart before any Playwright run.

Parallel stack from a clean worktree (for side-by-side comparison with a branch): after `git worktree add --detach`, symlink each `node_modules` from the main checkout into the new worktree at the same relative path, copy every `.env` from the main checkout, and rewrite the database URL to the port the local database listens on. Pass the new port into each backend CORS env var it reads (store, admin, auth) at launch, or logins and API calls from the new origin fail. Start each server with `nohup ... & echo $! > <scratch>/<name>.pid`, then wait with a background Monitor that polls the health URL and greps the log for `EADDRINUSE` or `Error:`. Do not block the foreground on the wait. A Bash call that chains `sleep N` (N around 30 or more) with other commands is blocked by the harness, and chaining shorter sleeps to get around it is also blocked. Run the job in the background and wait with Monitor: `until grep -qE "passed|failed" <log>; do sleep 5; done`.

Restarted admin pages can crash in the browser while `/app/login` still answers HTTP 200. The page shows "Failed to fetch dynamically imported module" because the browser requests a Vite dep chunk hash the new server no longer serves (404, or 504 "Outdated Optimize Dep"). Fix: stop the server tree you own, clear `node_modules/.vite` in your own worktree's backend, start it again, and confirm `/app/login` renders a form with `input[name="email"]` before any capture. Restart one server at a time: in the trace, stopping the second server and restarting the first alone cleared the crash. Two worktrees whose `node_modules` share one install also share one `.vite` cache, so two admin dev servers break each other's login. Run one admin dev server at a time, or give each worktree its own install.

Next.js app restart (seller-center, storefront): after stopping your own tree and starting it again, clear `.next` in your own app directory, then grep the served stylesheet for a class you just added (`curl -s localhost:<port>/_next/static/css/app/layout.css | grep -c <class>`). A correct stylesheet proves the server only; the browser side is in the shared-component item of the design board checklist in playwright-capture-verify.

A backend start can die before it listens: `kp-backend-dev.sh` lints first, and a lint error prints `Dev server not started.` and exits. Read the log tail for that line before polling the health URL. A health loop on a dead start prints 000 for minutes; stop polling and fix the lint error.

Launcher env: start a server through its repo launcher script when that script exports secrets or URLs, not as a bare command. A hand-started mock or backend without them fails in a non-obvious way (for example a 503 `not_configured` on a redeem call), and a test run can then pass through a broken step. Before any manual restart, read the launcher's export lines and pass them along.

Backend source edits need a restart of your own server too. A Medusa dev server started before the edit keeps serving the old route code, so a new JSON field is missing from the API response and the UI that reads it silently drops the element. Restart your own backend on its port, then read the new field in the API JSON before any capture.

Wrap-up is no exception to step 2. Do not stop a port with `kill $(lsof -ti :<port>)`; that kills whatever listens, including another session's server. Stop the pid recorded at launch (step 3) after the cwd check, then run the step 4 check.
